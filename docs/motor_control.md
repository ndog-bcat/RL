# Motor Control Specification v1.0

- 프로젝트: RL Cat Toy — 모터 제어기 / 강화학습 시뮬레이터 공통 규격
- 결정일: 2026-11-08
- 상태: **운용 정책 확정(v1.0)**. 물리적 한계나 모든 조건의 안정성이 검증됐다는 뜻은 아님. **2026-11-08 개정: 유지 하한 80→60, 모든 방향 전환에 정지 0.5초 유지.**
- 범위: 모터 **1개**의 방향 및 PWM 제어. 실제 이동속도·위치는 별도 동역학 모델에서 처리.

## 1. 실험에 기반한 운용 파라미터

| 파라미터 | 값 | 정의 |
|---|---:|---|
| `PWM_STOP` | `0` | 모터 구동 차단(coast), 제동(brake) 아님 |
| `PWM_START` | `90` | 정지 상태에서 기동할 때의 고정 PWM |
| `PWM_RUN_MIN` | `60` | 정상 구동 중 최소 허용 PWM(운용상 선택값; 간헐적 정지 가능성 미해소) |
| `PWM_RUN_MAX` | `180` | 정상 구동 중 최대 허용 PWM(전원 장애 위험을 피하기 위해 설정한 운용 제한) |
| `T_REVERSE_STOP` | `0.5 s` | 방향 전환 시 **현재 PWM에 관계없이** 정지 명령 **응답 후** 반대 방향 기동까지의 대기시간 |
| `T_START` | **`1.0 s` (임시 기본값)** | PWM 90으로 기동 상태를 유지하는 시간; 과거 실험 설정값이며 최종 검증 전 |
| `HEARTBEAT_INTERVAL` | `0.25–0.30 s` | 구동 중 ESP32에 현재 PWM을 주기적으로 재전송 |
| `ESP32_WATCHDOG` | `1.5 s` | 마지막 구동 명령 이후 자동 정지하는 펌웨어 타임아웃(현재 구현 기준) |

방향은 `dir = +1`(정방향), `dir = -1`(역방향)으로 정의한다. 정·역방향의 실제 장난감 이동 방향은 설치 구조에 따라 해석한다.

> 이 규격의 90/60/180/0.5초는 실험을 근거로 선택한 **실용적 제어 정책**이다. 180 이하에서 전원 문제가 절대 발생하지 않는다거나 0.5초면 항상 회전축이 완전히 멈춘다고 증명한 것은 아니다.

## 2. RL Action 규격

- 에이전트 출력: 단일 스칼라 실수 `a ∈ [-1, 1]`
- `a > 0`: 정방향 요청
- `a < 0`: 역방향 요청
- `a == 0`: 정지 요청

정상 구동 중 목표 출력은 다음과 같이 계산한다.

```python
if a == 0:
    target_pwm = 0
    target_dir = 0  # 방향 무관, 정지 처리
else:
    target_dir = 1 if a > 0 else -1
    target_pwm = round(60 + 120 * abs(a))
```

| Action | 정상 구동 시 목표 출력 |
|---:|---|
| `-1.0` | `dir=-1, pwm=180` |
| `-0.5` | `dir=-1, pwm=120` |
| `-0.1` | `dir=-1, pwm=72` |
| `0.0` | `pwm=0` |
| `+0.1` | `dir=+1, pwm=72` |
| `+0.5` | `dir=+1, pwm=120` |
| `+1.0` | `dir=+1, pwm=180` |

**주의:** 이 매핑은 `a=0`에서 불연속이다. `a`가 0에 매우 가까워도 0이 아니면 PWM 약 60을 요청한다. v1.0에서는 임의의 데드존을 도입하지 않는다. 필요하면 학습 실험 후 별도 버전에서 변경한다.

또한 **목표 PWM**과 **실제로 즉시 적용할 PWM**은 다르다. `STOPPED`, `STARTING`, `REVERSING`에서는 제어기 상태 전이 규칙이 우선한다.

## 3. 제어기 상태 및 전이 규칙

상태: `STOPPED`, `STARTING`, `RUNNING`, `REVERSING`, `ERROR`.

### R1 — 정지 상태에서 기동

1. `STOPPED`에서 0이 아닌 Action이 들어오면 Action의 부호를 기동 방향으로 정한다.
2. **반드시 그 방향으로 PWM 90을 먼저 인가**하고 `STARTING`으로 이동한다.
3. `T_START`(현재 임시 기본 1.0초) 동안 기동 PWM 90을 유지한다.
4. 기동 시간이 끝나면 가장 최근의 목표 Action을 반영하여 `RUNNING`으로 이동한다. 정상 구동 PWM 범위는 60~180이다.

### R2 — 같은 방향으로 속도 변경

- `RUNNING`에서 목표 방향이 현재 방향과 같으면 매핑된 PWM 60~180을 적용한다.
- 정상 구동 중 요청 PWM이 범위 밖으로 나가지 않도록 제어기에서 제한한다.
- PWM 변화와 실제 회전속도 변화가 동일하거나 즉각적이라고 가정하지 않는다.

### R3 — 정상 정지

- 어느 상태든 `a == 0`이 요청되면 가능한 한 즉시 PWM 0으로 만들고 `STOPPED`로 이동한다.
- 이 정지는 **구동 차단(coast)**이다. 모터 축이 물리적으로 즉시 멈췄다는 뜻은 아니다.
- 중간에 예약된 기동/반전 절차도 취소한다.

### R4 — 구동 중 방향 전환

1. `RUNNING`에서 목표 방향이 현재 방향과 반대면 **현재 PWM이 60~80처럼 낮아도 예외 없이 PWM 0을 전송**하고 `REVERSING`으로 이동한다.
2. 정지 명령이 정상 응답한 시점부터 `0.5초` 기다린다.
3. 반대 방향으로 PWM 90을 인가하고 `STARTING`으로 이동한다.
4. `T_START` 이후 정상 구동 범위(60~180)의 최신 목표 PWM을 적용한다.
5. **회전 중 직접 급반전 명령은 전송하지 않는다.**

### R5 — 전이 진행 중 새 Action

- 기동 또는 반전 대기 중 들어오는 Action은 최신 요청값으로 갱신한다.
- 정지 Action은 항상 최우선으로 처리해 기존 전이를 취소한다.
- 방향 전환 중 또 다른 방향 요청이 들어오는 경우, 재기동할 방향은 실제 기동 시점에 최신 Action을 기준으로 결정한다(정지 명령은 별도 우선).
- Action 갱신과 0.5초/1초 대기는 `sleep`으로 학습·통신 루프를 무조건 정지시키기보다 상태와 경과시간으로 관리하는 것을 목표로 한다.

### R6 — 장애 처리

- 명령 전송 실패·ESP32 재부팅 감지 등 통신 이상 시 가능한 경우 PWM 0 정지를 요청하고 `ERROR`로 이동한다.
- 정지 HTTP 요청에 대한 응답이 없으면 실제 정지를 보장할 수 없다. 기존 펌웨어의 1.5초 명령 타임아웃은 추가적인 보호수단일 뿐이다.
- `ERROR` 이후 **자동 재기동/무한 재시도 금지**. 상태 확인 후 사용자 또는 상위 안전 제어기가 명시적으로 재활성화해야 한다.
- **모터의 물리적 정지/실속은 현재 센서 없이 자동 감지할 수 없다.** 명령된 PWM과 실제 회전을 구분한다.

## 4. 실제 하드웨어와 시뮬레이터의 역할 분리

```text
RL Agent  -- action ∈ [-1, 1] -->  MotorController (공통 상태 전이·변환)
                                         |
                             +-----------+-----------+
                             |                       |
                         Hardware                 Simulator
                       ESP32 Client             Motor Dynamics
                             |                       |
                       PWM/Direction            위치/속도 업데이트
                             |                       |
                       Motor Driver              가상 장난감
```

- **MotorController:** Action → 목표 방향·PWM, 기동·정지·반전 규칙, 시간 기반 상태 관리.
- **Hardware adapter:** `GET /motor?speed=N&dir=1|-1`, `GET /stop`, `GET /status` 전송; 주기적 갱신·통신 오류 감지.
- **Simulation adapter:** MotorController가 생성한 명령의 시간을 동일하게 재현. PWM → 실제 속도/가속도/마찰은 별도 실측 기반 모델로 구현.
- **RL 환경:** 모터 제어 지연·현재 동작 상태가 다음 행동의 실행 가능성에 영향을 주므로, 에이전트 관측에 제어기 상태/남은 전이 시간 등을 포함할지 검토한다.
